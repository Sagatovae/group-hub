# Объявления сайта → Telegram @IDB2609

## Подключение

1. В Telegram создайте бота через @BotFather: `/newbot`. Добавьте его администратором канала @IDB2609 с правом публикации сообщений.
2. В Supabase → Edge Functions → Secrets сохраните:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `TELEGRAM_CHANNEL_ID` — `@IDB2609`;
   - `TELEGRAM_DISPATCH_SECRET` — случайная строка не менее 32 символов.
   Ключ `SUPABASE_SERVICE_ROLE_KEY` предоставляется серверной средой Supabase. Ни один из этих секретов не должен попадать в VITE-переменные, репозиторий или браузерный код.
3. В Supabase Vault сохраните тот же секрет диспетчера с именем `telegram_dispatch_secret`. Используйте интерфейс Vault, чтобы не оставлять секрет в SQL-истории.
4. Выполните `migrations/20261019_telegram_outbox.sql` в SQL Editor. Миграция применяется один раз. Она не переносит существующие объявления.
5. Опубликуйте функцию `telegram-publisher` из `functions/telegram-publisher/index.ts` через Dashboard либо `supabase functions deploy telegram-publisher --project-ref tqmzpwzjpoppbxvavuwn --no-verify-jwt`. Проверка JWT отключена для планировщика; каждый запрос проверяет собственный серверный секрет `x-dispatch-secret`.
6. Выполните `setup/telegram_schedule.sql`. Планировщик вызывает обработчик каждую минуту, компьютер держать включённым не нужно.

## Поведение

- Отправляются только вновь созданные объявления группы, а не материалы предметов. Правки и удаления уже опубликованных объявлений не синхронизируются.
- Публикуются заголовок, текст и указанное авторство. Длинный текст разбивается на сообщения без HTML-разметки.
- Затем отправляются вложения: JPEG/PNG как фотографии, другие поддерживаемые файлы как документы. Внешние ссылки отправляются ссылками. Файлы скачиваются сервером только из публичного bucket `materials` этого проекта; токен Telegram не раскрывается в ссылках.
- За один запуск отправляется одна часть: текст или файл. Поэтому первый текст обычно появляется в течение минуты; каждое последующее вложение — в следующую минуту. При большой очереди задержка увеличивается.
- Сбой не отменяет сохранение объявления на сайте. Отправленные части сохраняют прогресс, неотправленные повторяются до 12 неудачных попыток подряд. После этого задача остаётся в очереди для ручного разбора.
- При сетевом обрыве после принятия сообщения Telegram, но до сохранения прогресса, возможен повтор: Bot API не предоставляет идемпотентный ключ для sendMessage/sendDocument.
- Очередь содержит копию объявления на момент создания. Любой посетитель, который может создать объявление на сайте, тем самым инициирует публикацию в канале.

## Управление

В SQL Editor для просмотра состояния (доступно только администратору):

```sql
select id, material_id, next_part, attempts, sent_at, last_error
from public.telegram_outbox order by created_at desc;
```

После устранения причины сбоя возобновите конкретную задачу, подставив её UUID:

```sql
update public.telegram_outbox
set attempts = 0, available_at = now(), lease_until = null
where id = 'UUID' and sent_at is null;
```

Остановка автоматической отправки:

```sql
select cron.unschedule('telegram-publisher');
```

Тестовые сообщения автоматически не отправляются. Для включения интеграции нужны настроенные секреты, опубликованная функция и SQL-планировщик.
