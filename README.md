# Группа · Group Hub

Учебное пространство университетской группы. React + TypeScript + Vite, Supabase и PWA. Интерфейс на русском языке, адаптирован для телефона и компьютера.

## Первая версия

- Объявления группы, закрепление и поиск.
- Предметы и фильтр по семестру.
- Разделы: лекции, семинары, домашние задания, лабораторные, прочее; создание и переименование разделов.
- Блоки с текстом, дедлайном, несколькими файлами и внешними ссылками.
- Создание, редактирование и удаление блоков; создание предметов.
- Избранное на текущем устройстве, список ближайших дедлайнов.
- Общий каталог блоков с вложениями.
- Вход старосты через Supabase Auth; запись защищена RLS в базе и Storage.
- Устанавливаемая PWA с иконками, офлайн-оболочкой, последней сохранённой копией текстов и запросом обновления.

Название группы сейчас задано в `src/App.tsx` как пример «ИДБ-26-09». Его можно заменить.

## Локальный запуск

Требуется Node.js **22.12+**, рекомендуется Node.js 24 LTS (см. `.nvmrc`).

На macOS можно запустить `start.command` двойным щелчком: он откроет локальный сайт и использует встроенный Node.js Codex Desktop, если тот установлен. Окно терминала нужно оставить открытым на время работы сайта.

```bash
npm install
npm run dev
```

Откройте адрес из вывода Vite. Без `.env` работает **деморежим**: есть примеры материалов, кнопка «Попробовать редактор», данные и файлы сохраняются в IndexedDB только текущего браузера. Это не совместная база. При очистке данных сайта демоматериалы удаляются.

```bash
npm test
npm run build
npm run preview
```

PWA проверяется через production-сборку (`build` + `preview`), а не dev-сервер.

## Подключение общей базы Supabase

1. Создайте бесплатный проект в [Supabase](https://supabase.com/dashboard).
2. В SQL Editor выполните `supabase/schema.sql` **один раз на новом проекте**. Схема создаёт таблицы, правила доступа, транзакционную функцию создания предмета и публичный bucket `materials`.
3. В Authentication → Users создайте пользователя старосты с почтой и паролем. Не указывайте пароль в коде или GitHub.
4. Скопируйте UUID пользователя и выполните отдельный SQL-запрос:

   ```sql
   insert into public.administrators(user_id) values ('UUID_ПОЛЬЗОВАТЕЛЯ');
   ```

5. Отключите публичную регистрацию в настройках Authentication, если она не нужна. Другой зарегистрированный пользователь всё равно не получает права старосты.
6. Скопируйте `.env.example` в `.env` и заполните URL проекта и **publishable key** (либо legacy anon key):

   ```dotenv
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=your-public-publishable-key
   VITE_BASE_PATH=/
   ```

7. Перезапустите Vite. В деморежиме созданные данные автоматически в Supabase не переносятся. Общая база изначально пустая: войдите старостой и добавьте свои предметы.

**Никогда не используйте `service_role` / secret key в клиенте**. Все `VITE_*` переменные доступны посетителям. Доступ к записи обеспечивает RLS, а не секретность публичного ключа.

### Доступ и файлы

Материалы и загруженные файлы в этой версии доступны всем по ссылке. Это осознанная модель открытого пространства группы. Для закрытой группы потребуются вход студентов и отдельные правила чтения; пароль в интерфейсе этого не заменит.

Файл ограничен **10 МБ** в форме и bucket. Допустимы PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, TXT, ZIP, PNG/JPEG/WebP. Большие материалы загружайте в своё облако и добавляйте ссылкой. Автоматической интеграции с Google Drive нет. При изменении доступа к внешнему файлу ссылка может перестать работать.

Free tier Supabase ограничивает объём базы, Storage и исходящий трафик; проект может приостанавливаться после неактивности. Проверяйте [текущий тариф](https://supabase.com/pricing). Периодически сохраняйте резервную копию базы и оригиналы файлов.

## Публикация на GitHub Pages

Репозиторий подготовлен для бесплатной публикации, но workflow публикации запускается **вручную**:

1. Settings → Pages → Source → **GitHub Actions**.
2. Для общей базы добавьте в Settings → Secrets and variables → Actions → **Variables** переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` (только публичный ключ). Без них опубликуется демоверсия.
3. Actions → **Publish to GitHub Pages** → Run workflow.
4. Сайт будет доступен на `https://sagatovae.github.io/group-hub/` после успешного запуска. Этот адрес не означает, что сайт уже опубликован.

`VITE_BASE_PATH` в workflow определяется именем репозитория. Hash-навигация позволяет открывать страницы предметов напрямую без 404 на GitHub Pages. Workflow `Check` проверяет тесты и сборку при push / pull request.

## Что умеет PWA

После первого посещения production-сайта браузер сохраняет оболочку приложения. Установка доступна через меню поддерживаемого браузера («Установить» / «На экран Домой»). При недоступной базе отображается последняя сохранённая копия данных с запретом редактирования. При обновлении сайта показывается предложение перезагрузить приложение.

Кеш не гарантирует свежесть материалов и может быть удалён браузером. Облачные вложения не скачиваются автоматически для офлайн-работы; избранное сохраняет ссылку на блок, а не копию файла. Push-уведомления, синхронизация избранного между устройствами и офлайн-редактирование в эту версию не входят.

## Проверка общей базы перед использованием

Автоматические локальные тесты не заменяют проверку RLS на вашем Supabase. После установки схемы проверьте:

- Анонимный посетитель видит материалы, но не может создавать / изменять / удалять записи или загружать файлы.
- Авторизованный пользователь без строки в `administrators` также не может менять материалы.
- Назначенный староста создаёт предмет с разделами, публикует блок, прикрепляет файл и удаляет его.
- Изменения видны во втором браузере после обновления.

Подключение и эти проверки требуют созданного проекта Supabase и не выполнены в демоверсии.
